# 架构

## 总览

```
Godot 进程（一个窗口）
├─ autoload（project.godot 中的顺序）
│   CapooConfig     读角色表 / 动作表 / 参数表
│   AppSettings     设置 + 桌面上的咖波名单（user://settings.json）
│   DesktopWindow   透明覆盖窗口、点击穿透、置顶、单实例、帧率策略
│   Sfx             音效
└─ scenes/main.tscn
    Main (Main.cs)              托盘命令分发、命令行参数
    ├─ DesktopWorld             地面、墙、窗口顶边平台（WindowTracker）
    ├─ PetManager               所有咖波：召唤回收、存档、鼠标路由、碰撞、叠罗汉、作息
    │   └─ CapooController ×N   一只咖波：物理 + 状态机 + 鼠标交互
    │       ├─ CapooView        Spine 身体 + 部件层
    │       └─ 召唤/回收烟雾     与 CapooView 平级
    ├─ UI (MagicBook)           书本按钮、魔法书、右键菜单（PetContextMenu）
    ├─ TrayIcon                 托盘图标
    └─ DebugOverlay             调试信息（托盘开关）
```

坐标约定：覆盖窗口铺满一块屏幕的**工作区**（不含任务栏），窗口左上角在屏幕坐标 `DesktopWindow.Origin`。所以 **世界坐标 = 屏幕像素 − Origin**，地面就是窗口底边（任务栏顶部）。Godot 视口不缩放，1 个世界单位 = 1 个物理像素（项目开启了 DPI 感知）。

## 窗口与点击穿透（DesktopWindow）

1. **启动**：`_EnterTree` 先把 Godot 窗口藏起来，避免闪出黑窗。`_Ready` 里：
   - 取原生句柄（`WindowGetNativeHandle`）。
   - 设置透明模式。
   - 把窗口铺满所选屏幕的工作区（`ScreenGetUsableRect`）；如果工作区等于整个屏幕（任务栏自动隐藏），高度减 1 px，防止驱动把它当成全屏而关掉透明。
   - 加上样式：`WS_EX_TOOLWINDOW`（不在任务栏 / Alt-Tab 中显示）、`WS_EX_NOACTIVATE`（点咖波不抢焦点）。
   - 最后显示窗口。
2. **透明**：
   - 逐像素（默认）：Godot 的透明窗口（DWM），背景清成透明黑。
   - 颜色键（备用）：在此基础上 `LWA_COLORKEY` 抠掉纯黑，用于驱动不认 alpha 的显卡。
3. **点击穿透**：每帧用 `GetCursorPos` 取光标，换算成世界坐标，问一圈「这里有没有东西」：
   - 已登记的界面控件（`RegisterInteractive`）；
   - 命中测试器（`AddHitTester`，PetManager 登记了「光标下有没有咖波」）；
   - `ForceOpaque`（拖拽中）。

   没有东西时加上 `WS_EX_LAYERED | WS_EX_TRANSPARENT`，点击就穿透到下面的窗口。不用 Godot 的 `WindowSetMousePassthrough`，因为它会把绘制也裁掉。
4. **维护**：Godot 修改窗口标志时会整个重写 `GWL_EXSTYLE`，所以每 2 秒检查一次样式，被改掉了就补回来，并重新置顶。工作区变化（任务栏移动、分辨率变化）时重新铺满并通知 `ScreenChanged`。
5. **帧率策略**：
   - 窗口隐藏时 5 fps。
   - 低功耗模式下，没人碰咖波和界面时 30 fps。
   - 拖拽、飞行、摸摸、界面打开时用设置的上限。
6. **单实例**：命名互斥量 `CapooDesk.SingleInstance`。第二个实例直接退出，并且不读写名单。`--test` 运行用另一个互斥量，不会和正在用的程序互相影响。

## 物理（DesktopWorld + CapooController）

| 层 | 位 | 内容 |
|---|---|---|
| World | 1 | 地面（任务栏顶）、天花板、左右墙：`WorldBoundaryShape2D` |
| Platform | 2 | 其他窗口顶边未被遮挡的部分：单向 `SegmentShape2D`，StaticBody2D 带 `hwnd` 元数据 |
| Pet | 4 | 咖波身体，只和 World、Platform 碰撞；咖波之间不做刚体碰撞 |

- **窗口平台（WindowTracker）**：
  - 每 0.25 秒用 `EnumWindows` 从前往后枚举窗口，边界取 DWM 实际可见边框。
  - 排除：自己、隐藏、最小化、被 cloak 的、工具窗口、外壳窗口、`WS_EX_TRANSPARENT` 的悬浮层。
  - 对每个窗口的顶边，减去它前面窗口遮住的部分，剩下的宽度 ≥ 60 px 才算平台。
  - 最大化窗口和贴着屏幕顶边的窗口不算平台，但仍然算遮挡。
  - 有咖波站着的窗口每个物理帧都追踪位置，窗口移动时咖波跟着平移（`CarryPetsOn`）。
- **咖波身体**：
  - 原点在脚底；物理形状是身体轮廓 0.55×0.8 的矩形。
  - 重力 2200 px/s²，最大下落 4000 px/s，抛出速度上限 3500 px/s。
  - 地面上的状态由走/跑速度决定水平速度；飞行中撞墙按 −0.45 反弹。
  - 站着不动的咖波跳过 `MoveAndSlide`，每 8 个物理帧 `TestMove` 一次检查脚下还有没有东西；没东西超过 0.1 秒就开始下落。
- **落地**：播 `fall`；冲击速度 > 2500 → 晕，> 3300 → 灵魂出窍。
- **咖波之间**（PetManager，处理优先级 10，在咖波之后运行）：
  - **叠罗汉**：下落的咖波脚底穿过另一只的头顶线（水平偏差 < 0.3 身宽）时叠上去。上面的变成 Stacked（趴着），下面的播 stackDown。最多 12 层。整摞每帧跟随最下面那只（拖拽、抛出也跟着）。最上面的过 25–70 秒自己跳下来。
  - **撞晕**：飞行速度 > 1100 的咖波与地上的咖波重叠时，对方晕，自己反弹。
  - **软分离**：站着不动又重叠太多的咖波以 ≤ 30 px/s 慢慢挪开。

## 状态机（CapooController.Behavior）

```
Appear（召唤烟雾 1 秒，角色在 0.45 秒整只出现）→ Idle | Air | Stacked
Idle（2–5 秒）→ Decide()
Walk / Run / Wild → Idle（到达目标、撞墙、超时） | Hop（走到窗口边缘跳下）
React（hit1-7、stackDown1-3）→ Idle | Stacked
Pet（被摸）→ Enjoy（停止摸 1 秒后）→ Idle | Stacked
Dragged → Roll（往上扔） | Air
Roll → Air（开始下落）→ Land → Idle | Dizzy；Air → Stacked（落在头上）
Hungry（气泡 45 秒）→ Eating（食物掉下 → 嚼 → 满足）→ Idle（吃饱表情）
Pooing → WaitCleanPoo（扫帚气泡 45 秒）→ PooRemoving → Idle
Sleepy → Sleeping → Waking → Idle
Stacked（趴着）→ Hop（25–70 秒后） | Air（底下的被拿走）
Recycle（回收烟雾，0.35 秒整只消失）→ 释放
```

- **Decide() 权重**（来自 `Game_Parameter.json`）：
  - 发呆 1、走 5、跑 1、冲刺 1。驮着别人时不跑不冲刺，夜里也少跑。
  - 饿 3、便便 3：只在计时器到点后才参与。
  - 小睡：白天 0.05，夜里 2.5。
- **用户离开**：系统空闲 ≥「离开后睡」分钟时，下一次 Decide 直接进入「睡到你回来」。用户回来后各自随机等 0.5–6 秒再醒。
- **照顾计时器**（CapooNeeds）：各等级的间隔见[用户手册](用户手册.md#设置齿轮书签)。没理会的饥饿会在半个间隔后再出现；吃完饭便便会提前一分钟。第一次请求的时间是随机错开的。

## 鼠标交互

- PetManager 统一路由鼠标，只交给最上层的那只咖波。气泡优先于身体，因为气泡常常和旁边或头上的咖波重叠。
- 单击：小于 0.25 秒且移动小于 10 px。饿了时是喂食，等扫便便时是清理，睡着时是叫醒，其余是被戳（0.4 秒冷却）。
- 长按 0.25 秒或移动 10 px 开始拖拽；松手时用最近 0.1 秒的光标速度抛出。
- 摸摸：不按键、光标在咖波上来回移动累计超过 260 px（按大小缩放）。
- 光标位置一律用 `DesktopWindow.CursorWorld`：窗口穿透时 Godot 收不到鼠标事件，但轮询的光标位置始终可靠。

## Spine 渲染（CapooView）

- 每只咖波 = 身体骨架（CapooView 本身）+ 挂在身体骨骼上的部件骨架：
  - 角色外观：脸、面饰、帽子、衣服、背饰、手持物、三个配饰。
  - 叠加层：mood、上下特效、对话气泡、食物、便便。
  - 召唤/回收烟雾：被移到 CapooController 下、与 CapooView 平级，这样隐藏角色时烟雾照常播放。
- 每个部件是一个 SpineSprite，放在跟随骨骼的 SpineBoneNode 下面，缩放 2.0。各部件对应的骨骼见 `.claude/skills/spine-animation.md`。
- **动作**：一个动作同时设置多层动画。空的 mood / 特效 / 气泡层会隐藏（与原版相同），食物和便便层要显式隐藏。
- **显隐**：
  - 召唤 / 回收时设置整个 CapooView 的 `Visible`。不能用 `SelfModulate`：spine-godot 用 SpineMesh2D 子节点画身体，`SelfModulate` 对它们无效。
  - 刚创建或重新显示时调用 `RefreshPose()`（`UpdateSkeleton(0)`），避免部件晚一帧出现。
- **朝向**：原画朝左，朝右时把 CapooView 的 `Scale.X` 取反，整只（包括气泡）一起镜像，和原版一致。
- **性能**：叠加层播 `hide_all` 两帧后停止处理并隐藏，下一次有动画时再唤醒；魔法书缩略图只在悬停时动。

## 点击判定（HitShapes）

- `tools/gen_hit_shapes.py` 离线读取每个 Spine 骨架的每个 slot、每个附件，把附件图片的 alpha 烘成 64×64 的位图和它覆盖的方框，写进 `assets/data/hit_shapes.bin`。会动的层用对应动画的平均姿势烘焙，其他层用骨架初始姿势。
- 运行时 `CapooView.HitTest`：
  1. 把点击点换算到每个部件精灵的局部空间。
  2. 读取每个 slot 当前的附件名。
  3. 查对应位图。

  只有画出来的地方才算点中，配件之间的空隙和隐藏的部件都不算。
- 读附件名要绕开 spine-godot 4.1 的一个 bug，见[开发指南](开发指南.md#已知的坑)。
- 已知限制：形状按固定姿势烘焙，不随骨骼动画实时变化。翻滚（整只旋转）时约有 15% 偏差，其他常见动作在 3%–7%。

## 魔法书（MagicBook）

- 按原版说明书截图（`img_manual_01`、`pc_img_manual_02`）排版，所有坐标都是背景图 `ui_pop_collection_01.png`（954×694）里的像素坐标。原版截图是同一张图的 0.726 倍。
- **书签**：画在封面上。程序从背景图里抠出左页边缘（页面轮廓线及其右边的部分），再画在书签上面，这样书签看起来是从页面下面伸出来的。当前页的书签伸得更出来。
- **图鉴页**：
  - 3×3 格 × 两页；格子用 `box_collection_bot_01`（米色）/ `_02`（绿色 = 在桌面上）。
  - 悬停时显示 `_05` 黄色边角和 `tips_name_01` 名字气泡。悬停由每帧检查光标位置决定，而不是 `mouse_entered`：覆盖窗口频繁切换穿透，鼠标进出事件不可靠。
- **设置页**：左页每项是「名称 + ◀ 深色值条（`bar_language_01` 九宫格）▶」，右页是两列原版勾选框和图标按钮；「怎么玩」在右页上方盖一张纸（`ui_pop_tooltip_02`）。
- **缩放**：正常屏幕上不缩放（缩放会让文字发糊），只有屏幕放不下时才整体缩小。
- **关闭**：点书外面时关闭（直接读鼠标按键状态，因为外面的点击已经穿透到别的程序了）。

## 存档（AppSettings）

- `user://` 指向 `%APPDATA%\CapooDesk\`（`project.godot` 设置了自定义 user 目录）。
- `settings.json` 包含所有设置和名单（每只咖波的角色索引、坐标、朝向）。
- 保存时机：退出时、每 60 秒、每次 `Apply()` 修改设置时。
- `--test` 运行改用 `settings_test.json`，并且每次自测开始前先恢复默认值。
