# 开发指南

## 环境

| 需要 | 说明 |
|---|---|
| 带 spine-godot 4.1 模块的 Godot 4.2.1 mono 编辑器 | 本机在 `D:\app\Godot\godot-editor-windows-mono\godot4.exe`（实际文件 `godot-4.1-4.2.1-stable-mono.exe`），已加入 PATH。普通 Godot 打不开这个项目（没有 Spine 节点）。 |
| 对应的导出模板 | `%APPDATA%\Godot\export_templates\4.2.1.stable.mono\`，同样是 Spine 定制版 |
| .NET SDK 6 以上 | `dotnet build` 用；项目目标是 net6.0 |
| `godot-nuget\` | 项目里的本地 NuGet 源，提供带 Spine 绑定的 GodotSharp 4.2.1 |
| Python 3 + Pillow | 只有重新生成点击形状时需要 |

### 为什么不能升级引擎

所有 Spine 素材都是 4.1 格式（`"spine": "4.1.23"`），而且没有原始 `.spine` 工程可以重新导出。spine-godot 的 4.1 分支只支持 Godot 4.1 / 4.2。换成新版 Godot 或 Spine 4.2 运行时，素材就读不了了。

## 构建与运行

```bash
cd D:/program/Godot/capoo
dotnet build                          # 要求 0 错误 0 警告
godot4 --path .                       # 运行（读写真实设置）
godot4 --path . -- --test             # 测试模式：用 settings_test.json、独立的单实例锁
godot4 --path . -- --debug-overlay    # 打开调试叠加层
```

也可以在 VS Code 里按 F5（`.vscode/launch.json` 会先 `dotnet build` 再启动 godot4）。

`--` 之后的参数是给程序自己的：

| 参数 | 作用 |
|---|---|
| `--test` | 用 `user://settings_test.json` 和独立的单实例锁，不影响正在用的程序 |
| `--debug-overlay` | 启动时打开调试叠加层 |
| `--spawn=N` | 启动时额外召唤 N 只随机咖波 |
| `--tmode=alpha` / `--tmode=colorkey` | 临时指定透明模式 |
| `--quit-after=秒数` | 若干秒后按托盘「退出」的流程退出 |
| `--selftest` 等 | 自测模式，见 [测试](测试.md) |

## 导出

```bash
godot4 --headless --path D:/program/Godot/capoo --export-release "CapooDesk" D:/program/Godot/build/CapooDesk/CapooDesk.exe
```

- 预设 `CapooDesk`（`export_presets.cfg`）的设置：
  - 导出全部资源，额外包含 `*.json, *.ico, *.bin`。
  - PCK 和 .NET 程序集都嵌进 exe，所以只有一个文件。
- 如果正在运行的 CapooDesk 占用了 exe，就先退出它，或者导出到别的文件名。
- exe 文件本身的图标需要 rcedit：在编辑器设置「导出 > Windows > Rcedit」里填好路径后再导出。没配置时只是 exe 图标为默认，托盘和窗口图标不受影响。
- 导出后可以直接对 exe 跑自测：`CapooDesk.exe -- --test --selftest`。

## 改素材

### 新增或替换图片、音效等资源

Godot 需要先导入新文件，否则从命令行运行时加载不到。没有 `--import` 参数，可以用导出一个临时包来触发导入：

```bash
godot4 --headless --path D:/program/Godot/capoo --export-pack "CapooDesk" C:/Temp/tmp.pck
```

或者打开一次编辑器。

### 新增 Spine 骨架

1. 把 `X.spine-json`、`X.atlas`、`X.png` 放进 `assets/spine/<部件文件夹>/`。
2. 在编辑器里运行 `batch_create_spine_resources.gd`（EditorScript），为每个 json + atlas 生成 `X.res`（SpineSkeletonDataResource）。
3. 重新生成点击形状（见下）。

### 新增角色

在 `assets/json/Capoo_Info.json` 加一行，字段说明：

| 字段 | 说明 |
|---|---|
| `body`、`face` | 身体和脸的骨架名（必填） |
| 其余部件字段 | 对应部件的骨架名，空字符串表示没有 |
| `*_Anim` | 部件播放的动画，一般是 `animation` |
| `back_hierarchy` | `0` 表示背饰画在身体后面 |
| `handIndex` | 1 表示有手持物，身体在第二轨播 `hand_prop_r_01` |
| `collider_Adjust` | 小体型角色的碰撞缩放（0.7） |

图鉴会自动多出一格（每页 18 格）。

### 新增动作

- 官方动作在 `Capoo_Action.json`，我们自己组合的动作在 `Capoo_Action_Extra.json`。两张表格式相同，会合并成一张。
- 每个动作给 body / face / mood / effectTop / effectBot / talk / appear / food / poo 各层指定动画名和是否循环（`"true"` / `"false"`）。
- 层动画的名字必须是该骨架里确实存在的动画；可用的名字见 `.claude/skills/spine-animation.md`。

### 重新生成点击形状

只要 Spine 骨架有任何变化都要重新生成：

```bash
cd D:/program/Godot/capoo
python tools/gen_hit_shapes.py      # 写 assets/data/hit_shapes.bin
godot4 --path . -- --test --hitareas   # 复查全部 126 个角色的点击范围
```

格式见 `HitShapes.cs`（魔数 `CAPOO_HITSHAPES2`）。注意项目的 Spine 运行时是 y 轴朝下的，生成器已经按这个约定计算骨骼矩阵。

## 代码约定

- 所有 Godot 节点类都是 `public partial class`，不用 namespace，Tab 缩进（见 `.editorconfig`）。
- 一个类可以拆在多个文件里（`CapooController.cs` / `.Behavior.cs` / `.Interaction.cs`）。
- 修改设置用 `AppSettings.Instance.Apply(s => ...)`：它会保存并触发 `Changed` 事件。
- 需要接收点击的界面控件必须调用 `DesktopWindow.Instance.RegisterInteractive(control)`，否则点击会穿透下去。
- 咖波的鼠标输入只走 PetManager（`HandleLeftPress` / `HandleLeftRelease`）。不要在单只咖波里读 `Input.IsActionJustPressed`，否则所有咖波会同时响应。
- 需要光标位置时用 `DesktopWindow.Instance.CursorWorld`（自测时它是虚拟光标）。
- 提交信息用英文，`feat:` / `fix:` / `perf:` / `test:` / `docs:` 前缀；只在本地 `desktop-pet` 分支提交。

## 已知的坑

| 坑 | 说明 |
|---|---|
| 不要定义和 Godot 类型同名的全局类 | 早期的 `CharacterBody2D.cs`、`Node2D.cs` 会悄悄遮蔽 `using Godot;` 里的同名类型。`Mutex` 在 Godot 和 System.Threading 里都有，要写全名。 |
| `SelfModulate` 隐藏不了 SpineSprite | spine-godot 用 SpineMesh2D 子节点绘制。要隐藏就用 `Visible`，或者把需要保留的东西移出这棵子树。 |
| Spine 部件晚一帧出现 | 不可见的 SpineSprite 不更新网格。刚创建或刚显示时调用 `UpdateSkeleton(0)`（`CapooView.RefreshPose`）。 |
| `SpineSlot.GetAttachment()` 的析构 bug | spine-godot 4.1 的 SpineAttachment 创建时不 `reference()`，析构时却 `dereference()`。被回收的包装对象会把引用计数减坏，退出时还可能访问已释放内存（`0xC0000005`）。读完后先触发资源的 `_internal_spine_objects_invalidated` 信号再 `Dispose()`，见 `CapooView.ReleaseSpineWrappers`。`GetSlots()` 返回的包装对象也要及时 Dispose。 |
| 隐藏部件的包围盒是无穷大 | 没有附件的骨架，`GetBounds()` 返回起点为 FLT_MAX、尺寸为负的矩形，要过滤掉。 |
| Godot 会重写窗口扩展样式 | 修改窗口标志（置顶、透明等）时 Godot 会整个重写 `GWL_EXSTYLE`，所以 DesktopWindow 要定期检查并补回自己的样式。 |
| `mouse_entered` / `mouse_exited` 不可靠 | 覆盖窗口在穿透和不穿透之间来回切换，鼠标进出事件会丢失或错乱。悬停用每帧检查 `CursorWorld` 来判断。 |
| `Performance.Monitor.TimeProcess` 不是 CPU 时间 | 它在这里约等于整帧时长（60 fps 时恒为 16.7 ms）。测性能要用 `Process.TotalProcessorTime`。 |
| 代码里新建的节点 | 父节点已在场景树里时，`AddChild` 才会立即触发 `_Ready`。所以要先加入树，再设置 Spine 动画。 |
