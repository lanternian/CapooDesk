## 问题 1：召唤 / 回收时身体和表情、配件不同步（高）

**现象**【图1】
- 召唤：0.05–0.30 秒烟雾里只有身体，没有脸、帽子、手持物；到 0.42 秒脸和配件才一起出现。
- 回收：0.35 秒脸和配件消失，烟雾散去后（约 0.60 秒）还剩一个没有脸的身体，直到 0.85 秒节点被删除。

**根因**
1. **身体根本没被隐藏。**
   - `CapooView.SetCharacterVisible`（[scripts/CapooView.cs:344](../scripts/CapooView.cs)）用 `SelfModulate = Transparent` 隐藏身体。
   - 但 spine-godot 的 `SpineSprite` 不自己画，而是为每个 slot 创建 `SpineMesh2D` 子节点来画（`SpineSprite.cpp:460-465`）。网格颜色只取骨架色和 slot 色（`SpineSprite.cpp:708-710`），不受父节点 `SelfModulate` 影响。
   - 脸和配件是用 `Visible = false` 隐藏的，这个有效。结果就是身体一直可见、其余部件按时显隐，两边不同步。
2. **首帧滞后。**
   - 新建或刚变为可见的部件精灵要晚一帧才更新网格。不可见时 `update_skeleton` 会直接跳过 apply（`SpineSprite.cpp:674`：`if (!is_visible_in_tree()) return;`）。
   - 召唤时被烟雾挡住不明显，但魔法书缩略图能看出来，见问题 2-1。
3. **遗漏的层。** mood / 特效 / 对话气泡 / 食物 / 便便这些叠加层不在 `characterParts` 里，召唤或回收的隐藏阶段如果它们正在显示，不会被藏起来。

**相关代码**
- `SetCharacterVisible`：[CapooView.cs:344](../scripts/CapooView.cs)
- `characterParts` 收集：`AttachPart`，[CapooView.cs:92](../scripts/CapooView.cs)
- 叠加层注册：[CapooView.cs:434](../scripts/CapooView.cs) 起
- 状态时序：Appear 在 [CapooController.Behavior.cs:55](../scripts/CapooController.Behavior.cs) 和 `:194`（0.45 秒显示）；Recycle 在 `:165` 和 `:299`（0.35 秒隐藏，0.85 秒删除）

**修复方向**
- 用一个开关隐藏整只咖波：设置 `CapooView.Visible`，这样身体网格、全部部件和叠加层会同时显隐。
- 把召唤/回收烟雾（`efx_appears` 精灵）移出 `CapooView` 子树，改成 `CapooController` 下与 view 平级的节点，位置、缩放、朝向与 view 保持一致。这样咖波隐藏时烟雾照常播放。
- 新建咖波或重新显示前，在设置好动画后对身体和各部件调用一次 `SpineSprite.UpdateSkeleton(0)`，或者先隐藏、等 1 帧再显示，消除首帧滞后。

**验收**
- 召唤和回收的逐帧截帧里：身体、脸、配件在同一帧出现、同一帧消失。
- 烟雾全程可见，回收后不再残留身体。
- 截帧方法可参考 `SelfTest.Capture`，按时间点抓帧。

**已修复** — 提交 `5f702c1`
- `CapooView.SetCharacterVisible` 改为隐藏整个 `CapooView`（`Visible = false`），身体网格、脸、配件和 mood/特效/气泡/食物/便便这些叠加层一起显隐。`SelfModulate` 对 `SpineMesh2D` 子节点无效，所以原来身体一直可见。
- 召唤/回收烟雾 (`efx_appears`) 从 `CapooView` 子树移到 `CapooController` 下与 view 平级，缩放按身体骨架 root 骨骼（0.5 / 0.4）折算，位置、朝向与原来一致。
- 新增 `CapooView.RefreshPose()`：刚创建或刚显示的部件立即 `UpdateSkeleton(0)`，消除首帧滞后。
- 验证：`-- --test --selftest` 新增 `CheckSummonSync`，逐帧统计蓝色身体 / 粉色脸 / 黄色安全帽的像素数，召唤时前 7 帧三者都是 0（只有烟），之后同一帧一起出现；回收时三者同一帧一起消失。逐帧对比图见 `fixed/1_召唤与回收逐帧.png`。

## 问题 2：魔法书排版（中）

都在 [scripts/MagicBook.cs](../scripts/MagicBook.cs)。

1. **翻开第一帧缩略图只有身体**【图2 左】
   - 打开魔法书或翻页时，18 张卡片的第一帧都没有脸和帽子，0.1 秒后才补齐。根因同问题 1-2。
   - 卡片在 `MakeCard`（`:382`）创建，0.2 秒后冻结处理。
   - 修复：创建后立即 `UpdateSkeleton(0)`，或者先隐藏卡片、下一帧再显示。
2. **悬停提示框难看又难读**【图3】
   - `TooltipText = info.name`（`:391`）用的是 Godot 默认的深灰提示框，却套了主题的深棕字，几乎看不清。
   - 它还挡住缩略图，而且名字已经写在卡片下方了。
   - 修复：去掉 tooltip；或者给 `TooltipPanel` / `TooltipLabel` 加主题样式（浅纸色底、深棕字）。
3. **右上角拥挤**【图4】
   - 关闭按钮 X（`:264`，坐标 `(780, 96)`）压在页面右上角的折角上，又紧贴第一个书签。
   - 右对齐的状态文字“桌面上 n / m 只”（`:339`）也伸进了折角。
   - 修复：重新安排关闭按钮的位置，状态文字留出折角的宽度。
4. **书签像贴纸贴在书上**【图4】
   - 书签（`:249`，`x = 836`）画在封面和页边之上，右侧平切的边缘露在外面，第三个书签又碰到了肉球气泡装饰。
   - 修复：把书签放到书本背景之后（先加入节点，或设置 z 顺序），只让它从封面下面露出来；同时调整纵向间距，避开肉球。
5. **底部拥挤**【图5】
   - 翻页箭头和页码（`:345`、`:478`，`LeftPage.End.Y - 30`）挤在页面底部卷边上，和最后一行卡片之间没有间距。
   - 桌面页只有 1 页时箭头仍然显示为可点。
   - 修复：给卡片网格和底部之间留出间距（可以把 `CardRows` 或行高调小一点）；只有 1 页时隐藏或禁用箭头。
6. **设置页右栏溢出**【图6】
   - “饿/便便 关/少/中/多”一行、“离开多久后睡 … 10 分钟”一行顶到了右页边。原因是标签的最小宽度 120（`:637`、`:674`）加上按钮和数值标签，超过了 VBox 的宽度（`:602`）。
   - 选择按钮选中和未选中的颜色太接近。
   - 修复：缩小标签宽度或改成两行布局，让行宽不超过页宽；选中态用更深的底色或加描边。
7. **文字整体偏小**
   - `uiScale = 屏幕高 / 1300`（`:195`）没有考虑 Windows 的 150% 缩放。卡片名 13 px、提示 15–16 px，在 150% 缩放下相当于 9–11 px。
   - 另外书本是整体 `Control.Scale` 缩放的，文字会略微模糊。
   - 修复：缩放时把 `DisplayServer.ScreenGetScale()` 或 DPI（144 = 150%）考虑进去，保证 1080p 屏也放得下；或者直接改字号而不是整体缩放。

**验收**
- 三个页签在 2240×1328（150% 缩放）和 1920×1040（100% 缩放）两种尺寸下截图，元素互不重叠，也不超出纸面。
- 打开书和翻页的第一帧缩略图就完整。

## 问题 3：点击/拾取范围过大，点在咖波旁边也有反应（高）

**现象**【图7】
红色 = 身体轮廓比画面大出来的部分，橙色 = 配件包围盒比画面大出来的部分；采样步长 2 px，面积约为采样点数 × 4。

| 角色 | 实际画面 | 可点击包围盒 | 空白却可点击 |
|---|---|---|---|
| #0 咖波（默认那只） | 172×122 | **444×310** | 约 12 万 px²，几乎全部来自帽子 |
| #48 有錢咖波 | 288×170 | 332×172 | 约 1.9 万 px²，来自配件 |
| #40 手搖鈴聖誕咖波 | 222×180 | 266×174 | 约 1.7 万 px²，来自配件 |
| 其余 5 只 | — | 略大 | 约 1.5k–4.4k px²，来自身体轮廓 |

**影响**：同一个命中测试被三处使用。
- 点击反应：`PetManager.PickPet`（[PetManager.cs:160](../scripts/PetManager.cs)）。
- “摸摸”的蹭动检测（`:251`）：鼠标只是从旁边经过也会开始摸摸。
- 点击穿透（`DesktopWindow.IsInteractiveAt`）：这片区域里的点击会被覆盖窗口吃掉，传不到下面的桌面或程序。默认咖波周围就有一块 444×310 的点击死区。

**根因**
1. **隐藏的帽子被当成无限大。**
   - 默认咖波的 `capoo_hat_009` 通过播放 `hide_all` 隐藏，`hide_all` 会把附件置空。
   - 骨架没有任何附件时，Spine 的 `getBounds()` 返回非法矩形：起点是 FLT_MAX，尺寸为负。
   - `GetGlobalBounds`（[CapooView.cs:369](../scripts/CapooView.cs)，第 373 行）只过滤了尺寸为 0 的情况，非法矩形变换后近似无限大。
   - 于是 `HitTest` 的粗筛窗口（[CapooController.cs:145](../scripts/CapooController.cs)：横向 ±1.2 倍身宽，纵向从脚下 0.3 倍到上方 2.2 倍身高）全部算命中，正好就是测出来的 444×310。
2. **配件用整个骨架的轴对齐包围盒判定**（`AccessoryHitTest`，[CapooView.cs:360](../scripts/CapooView.cs)），把配件零件之间的空白也算了进去（有錢咖波周围的钞票、手搖鈴的铃铛等）。
3. **身体轮廓偏松。** `BodyOutline`（[CapooController.cs:12](../scripts/CapooController.cs)）是旧代码手调的多边形，比实际身体多出约 5–14 px（头顶多 14 px），而且没有按不同身体逐个适配，只乘了 `collider_Adjust`。

**修复方向**
- `GetGlobalBounds` 过滤非法包围盒（尺寸 ≤ 0 或非有限值）；当前处于 `hide_all`、没有附件的配件直接跳过。
- 配件改为逐个附件判定：region 附件按旋转矩形四角，mesh 附件按三角形，用 slot 的世界顶点（`ComputeWorldVertices`）计算；或者用 slot 级别的包围盒，而不是整个骨架的。
- 收紧身体轮廓，最好从身体骨架的实际附件生成，或按画面 alpha 生成一次后缓存。
- 对话气泡的命中（`BubbleHitTest` 和 `GetTalkBubbleRect`）也用 `GetGlobalBounds`，要一并检查。

**验收**
- 用同样的逐像素对比（命中但 alpha≈0 的面积）测这 8 个角色：“空白却可点击”降到画面面积的 10% 以内。
- 默认咖波的可点击包围盒和画面包围盒相差不超过约 10 px。
- 离咖波轮廓 15 px 以外的点击能穿透到桌面。

## 问题 4：饿了 / 扫便便气泡在咖波朝右时没有镜像（中）

**现象**【图8】
- 朝左时，气泡在左上方，尾巴朝右下指向头部，正确。
- 朝右时，气泡移到了右上方，但图形没有翻转：尾巴仍朝右下、背离头部，而且位置比真正的镜像更靠近头部，压到头上。

**证据**（相对脚底坐标）
- talk 骨骼位置镜像正确：(−99, −124) ↔ (+99, −124)。
- 扫帚气泡的范围：朝左时 x ∈ [−170, −90]，朝右时 x ∈ [+27, +109]。镜像后本应是 [+90, +170]，实际往头部偏了约 63 px。

**根因**
- `CapooView.SetFacing`（[CapooView.cs:336](../scripts/CapooView.cs)，第 340 行）在朝右时把 talk 精灵的 `Scale.X` 反设为 −2，本意是让“?”不显示成反的。
- 但气泡底板、尾巴和图标属于同一个 Spine 骨架，只能整体翻转，结果气泡没有跟着朝向镜像。
- 原版 Unity 版是整只咖波（包括气泡）一起镜像的。

**修复方向**
- 去掉这个反向翻转，让气泡随身体一起镜像，与原版一致。副作用：点击反应里的“?”“!”也会镜像，原版同样如此。
- 修完确认 `BubbleHitTest` 的点击区域仍跟随气泡（它用的是全局变换，理论上没问题）。

**验收**
- 饿了气泡（碗）和扫便便气泡（扫帚）在朝左、朝右两种情况下都是镜像对称的，尾巴指向头部，不压到头上。
- 点击气泡依然能喂食或清理（`--selftest` 里的相关检查要通过）。
